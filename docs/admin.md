# Админка базы знаний

Веб-интерфейс для управления документами ассистента: `http://<host>:8080/admin/`.

## Включение

В `.env`:

```env
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<длинный случайный пароль>
ADMIN_SESSION_TTL_MINUTES=480
ADMIN_COOKIE_SECURE=false   # true, когда сайт работает по HTTPS
ADMIN_MAX_UPLOAD_MB=50
```

Пустой `ADMIN_PASSWORD` — админка выключена, все `/v1/admin/*` отвечают `503`.
После изменения `.env` пересоздайте API: `docker compose up -d --force-recreate api`.

Сгенерировать пароль: `python3 -c "import secrets; print(secrets.token_urlsafe(18))"`.

## Вкладки

**База знаний** — исходники в `data/knowledge_sources`.

| Колонка | Значение |
|---------|----------|
| Сконвертирован | **Да** — есть актуальный `.txt`; **Устарел** — исходник изменён после конвертации; **Нет**; **Формат не поддерживается** (например, `.doc`) |

- **Загрузить** — pdf, docx, xlsx, txt, md (можно перетащить файлы на таблицу). Файл с тем же именем заменяется только после подтверждения.
- **Конвертировать** — пересоздаёт `.txt` для файла. Если `.txt` был переименован вручную, перезаписывается именно он (связь по заголовку `# source-file:`). Ручные правки в `.txt` при этом теряются.
- **Конвертировать новые и изменённые** — только файлы со статусом «Нет» / «Устарел».
- **Удалить** — удаляет исходник и связанный `.txt`. Из ответов ассистента документ пропадёт после следующего импорта.

**Импорт** — документы в `data/knowledge`. «Есть в Базе знаний» — документ проиндексирован и ассистент его видит.

- **Импорт** — полная пересборка индекса из всех документов (~1,5 минуты на текущем объёме).
  Новый индекс собирается в отдельной коллекции `<CHROMA_COLLECTION>__staging` и подменяет текущую только в конце, поэтому ассистент всё время отвечает по старой базе. При ошибке текущая база не меняется.

Изменения в `config/knowledge_sources.json` (названия источников, запрет скачивания) применяются без импорта.

## Безопасность

- Сессия — `httpOnly`, `SameSite=Strict` cookie на путь `/v1/admin`; хранится в памяти API (перезапуск API = повторный вход).
- 5 неудачных входов за 15 минут с одного IP блокируют вход на 15 минут.
- Загрузка: только разрешённые расширения, лимит размера, имя файла очищается от путей.
- В production включите HTTPS и `ADMIN_COOKIE_SECURE=true`; по возможности ограничьте доступ к `/admin/` по IP в nginx.

## API

Все эндпоинты, кроме `login`, требуют cookie сессии. Документация — Swagger `/docs`, раздел **admin**.

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/v1/admin/login` | `{"username", "password"}` → cookie |
| POST | `/v1/admin/logout` | Завершить сессию |
| GET | `/v1/admin/me` | Проверка сессии |
| GET | `/v1/admin/sources` | Список исходников |
| POST | `/v1/admin/sources` | Загрузка (multipart: `file`, `overwrite`) |
| DELETE | `/v1/admin/sources?name=…` | Удалить исходник и его `.txt` |
| POST | `/v1/admin/convert` | `{"name": "…"}` — один файл; `{}` — все новые и изменённые |
| GET | `/v1/admin/documents` | Документы и признак индексации |
| POST | `/v1/admin/ingest` | Запустить полный импорт (`409`, если уже идёт) |
| GET | `/v1/admin/ingest` | Статус и прогресс импорта |

```bash
B=http://localhost:8080
curl -c /tmp/c -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"…"}' $B/v1/admin/login
curl -b /tmp/c $B/v1/admin/sources | python3 -m json.tool
curl -b /tmp/c -X POST $B/v1/admin/ingest
```

## Разработка

```bash
cd apps/admin && npm install
npm run dev        # http://localhost:5174/admin/, /v1 проксируется на :8000
npm run build      # проверка типов + сборка в dist/
```

Если `npm install` зависает (недоступен IPv6): `NODE_OPTIONS=--dns-result-order=ipv4first npm install`.

## Архитектурные решения

- **Импорт выполняется в процессе API**, а не в контейнере `ingest`: API и импорт используют один клиент Chroma и одну модель эмбеддингов (нет рассинхрона `EMBEDDINGS_PROVIDER`, ошибки «collection does not exist» после recreate и повторной загрузки модели в память).
- Контейнер `ingest` (`docker compose --profile tools run --rm ingest`) оставлен для первичной индексации и аварийных случаев. Запускать его во время работы API не рекомендуется — после него API нужно перезапустить.
