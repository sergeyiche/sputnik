# Мультитенантность

Один процесс API обслуживает все организации. Какая из них отвечает на запрос, решает заголовок `Host`. Отдельного сервиса на организацию нет.

Базовый домен задаётся `PLATFORM_BASE_DOMAIN` (локально `spootnik.local`, на проде `spootnik.ru`).

## Адреса

| Хост | Что открывается |
|------|-----------------|
| `spootnik.ru`, `www` | Лэндинг: заявка и виджет организации `help` |
| `help.spootnik.ru` | Кабинет организации `help` и консоль оператора платформы |
| `admin.spootnik.ru` | Та же консоль оператора, запасной адрес |
| `{slug}.spootnik.ru` | Сайт и кабинет этой организации |
| `localhost`, `127.0.0.1` | Прежний режим без организации: общие каталоги `data/knowledge` и коллекция из `CHROMA_COLLECTION` |

Локально те же имена с доменом `spootnik.local` и портом виджета `8080`. Фонд уже работает на `parkinson.spootnik.ru`.

Nginx виджета смотрит на имя хоста. Корень домена отдаёт лэндинг. `help` и `admin` с корня переходят в `/admin/`. Любой другой поддомен получает демо-страницу со сниппетом виджета; API при этом всё равно выбирает организацию по `Host`.

## Как выбирается организация

`PlatformHostMiddleware` разбирает `Host` и кладёт результат в контекст запроса.

1. `localhost` и адреса тестов — режим `legacy`.
2. Корень домена и `www` — лэндинг.
3. `admin.{домен}` — консоль оператора.
4. Один уровень поддомена — организация с этим slug. `help.spootnik.ru` тоже организация, хотя slug `help` нельзя выбрать в заявке.
5. Всё остальное — неизвестный хост, чат отвечает 404.

Заявка принимается только с лэндинга. Консоль оператора (`/v1/platform/*`) открывается на `help`, `admin`, корне домена и в режиме `legacy`.

Slug — латиница, цифры и дефис, до 32 символов. Заняты `www`, `api`, `admin`, `app`, `mail`, `platform`, `static`, `widget`, `help`.

## Жизненный цикл

Статусы: `pending`, `active`, `rejected`, `suspended`.

1. Форма лэндинга вызывает `POST /v1/platform/register`: slug, название, почта и пароль владельца. Заявка остаётся `pending` и в чат не отвечает.
2. Оператор на `help` подтверждает заявку. Создаются каталоги, в `prompt_default.md` копируется `config/default_system_prompt.md`, статус становится `active`.
3. Отклонение ставит `rejected`. Чекбокс включения переводит уже подтверждённую организацию между `active` и `suspended`.
4. Чат, виджет и кабинет отвечают только при статусе `active`.

Почта и пароль владельца хранятся в `data/platform/platform.db` (хеш пароля). Почта обязательна. Если у владельца её не было, при открытии базы подставляется `{slug}@spootnik.local`. Локально письмо всё равно попадает в Mailcatcher (`http://localhost:1080`), настоящий ящик нужен только при `MAIL_TRANSPORT=mailtrap`. В `.env` остаются учётка оператора `ADMIN_USERNAME` / `ADMIN_PASSWORD`, ключ GigaChat и способ отправки: `MAIL_TRANSPORT=smtp` либо ключ Mailtrap.

На странице входа кабинета есть «Забыли пароль?». Письмо уходит только если почта совпадает с владельцем этого поддомена. Ссылка ведёт на `/admin/#reset=…` и действует `PASSWORD_RESET_TTL_MINUTES`. Повторный запрос гасит предыдущую ссылку.

Шаблон `config/default_system_prompt.md` содержит плейсхолдеры вроде `{{НАЗВАНИЕ_ОРГАНИЗАЦИИ}}`. Сейчас подтверждение копирует шаблон как есть. Организация правит текст во вкладке «Промпт». Подстановка значений из заявки в эти плейсхолдеры ещё не сделана.

## Что изолировано

| | Своё у организации | Общее |
|--|--------------------|--------|
| Файлы | `data/tenants/{slug}/` | — |
| Chroma | коллекция `tenant_{slug}` | один каталог Chroma на диске |
| Промпт | `prompt_default.md` и версии в `prompts/` | шаблон новой организации в `config/` |
| Сессия диалога | пространство имён по slug, заголовок `X-Session-Id` | — |
| Вход в кабинет | почта владельца, cookie на этот хост | — |
| GigaChat | учёт вопросов и токенов по организации | один ключ и одна модель |

У фонда коллекция остаётся `parkinson_kb`, не `tenant_parkinson`.

Каталог организации:

```
data/tenants/{slug}/
  knowledge/            .txt для индекса
  knowledge_sources/    исходники pdf, docx, xlsx
  prompts/              state.json и versions/
  branding/
  prompt_default.md     текст кнопки «Восстановить промпт по умолчанию»
```

`data/tenants/` и `data/platform/` в git не входят. Импорт из кабинета индексирует `knowledge` этой организации в её коллекцию.

`./scripts/docker-ingest.sh` по-прежнему читает общий `data/knowledge` и пишет в `parkinson_kb`. Для фонда после переноса файлов источник — `data/tenants/parkinson/knowledge`.

## Два входа

Имя cookie одно: `oracool_admin`. Путь и хост разные, атрибута `Domain` нет.

| Кто | Где | Cookie |
|-----|-----|--------|
| Оператор платформы | `POST /v1/platform/login`, логин из `ADMIN_USERNAME` | путь `/v1/platform` |
| Владелец организации | `POST /v1/admin/login` на своём поддомене, почта и пароль из базы | путь `/v1/admin` |

На `help.spootnik.ru` в админке два экрана: «Кабинет help» (база, промпт, виджет) и «Платформа» (очередь заявок, включение, расход GigaChat). `admin.spootnik.ru` открывает сразу консоль платформы.

## Виджет

Сниппет стоит на сайте организации и грузит скрипт со своего поддомена:

```html
<link rel="stylesheet" href="https://mycompany.spootnik.ru/widget/sputnik.css" />
<script src="https://mycompany.spootnik.ru/widget/sputnik.js" defer></script>
<sputnik-widget></sputnik-widget>
```

Запросы идут на origin скрипта, поэтому `Host` совпадает с организацией. Сессия передаётся заголовком `X-Session-Id`. Настройки внешнего вида (название, цвет, предупреждение, показ источников) отдаёт `GET /v1/widget/config` и хранятся в базе этой организации.

Лэндинг подключает виджет с `help.{текущий домен}`, чтобы ответы на корневой странице шли из базы `help`.

## База платформы

SQLite: `PLATFORM_DB_PATH`, по умолчанию `data/platform/platform.db`. В ней организации, владельцы, настройки виджета и суточные счётчики (вопросы, токены, пустые ответы, ошибки, 429 и 402). Тексты документов в базе не лежат.

Карточка ключа в консоли суммирует расход за 7 дней и запрашивает остаток кабинета GigaChat. Если API остатка недоступен, карточка пишет об этом и не роняет список организаций.
