# Промпт v3: глубина ответа и вовлечение

Дата: 24.11.2026. Прод: `41349ff`, активная версия промпта `20261124T161057Z-4e1cc0`, `LLM_MAX_TOKENS=1200`.

## Задача

Сделать ответы не «выжимкой из базы», а развёрнутой информационной поддержкой: 2–3 содержательных абзаца, точное попадание в вопрос, учёт контекста и один уместный вопрос в конце. При этом ассистент не лечит болезнь и не обещает излечение — он помогает человеку жить с БП.

## Что изменено

### Промпт

- Явно зафиксирована миссия: не вылечить, а помочь понимать, адаптироваться, сохранять самостоятельность и качество жизни.
- Добавлен блок «Сначала пойми смысл вопроса»: тип запроса, контекст, один уточняющий вопрос только при критической нехватке факта.
- Добавлен блок «Глубина ответа»: 2–3 абзаца, роли первого/второго/третьего абзаца, запрет на сухой список вместо объяснения.
- Переписан блок «Диалог и вовлечение»: содержательный ответ должен заканчиваться одним вопросом по теме; исключения — острые состояния, короткие реплики, просьба без вопросов.
- Убраны старые указания «пиши лаконично» и «вопрос по желанию», которые противоречили новой задаче.
- Сохранены запреты на назначения, дозы, выдуманные ссылки и обещания излечения.

### Runtime

- Добавлен контекстный навык `answer-depth` (всегда активен, добавляется после тематических навыков). Он задаёт формат 2–3 абзацев и обязательный вовлекающий вопрос.
- В пользовательское сообщение добавлен финальный формат-блок для tenant с `answer-depth`; это усиливает инструкцию в конце запроса.
- `LLM_MAX_TOKENS` по умолчанию 1200 — достаточно для 2–3 абзацев, но без «простыни».
- Короткие реплики («Спасибо», «Привет») не получают формат-блок: иначе ассистент отвечал мини-эссе на благодарность.
- Для суицидальных/кризисных формулировок добавлен жёсткий ответ с 103/112 без вопроса и без обращения к LLM.

### Навыки

- `medications`, `exercises`, `fund-projects`, `legal-social`: старые «короткие списки» заменены на 2–3 абзаца + компактный список, если он нужен.
- `rls`, `urinary`, `dbs`, `find-doctor` сохраняют свои точные форматы; для точных списков (врачи, DBS/FUS, проекты) структура остаётся списком.

## Живые проверки

| Запрос | Результат |
|---|---|
| «Что такое болезнь Паркинсона?» | 3 абзаца, объяснение + проявления + лечение/жизнь; в конце вопрос про аспект |
| «Что делать при запорах?» | 3 абзаца, причины → питание/режим → когда к врачу; в конце вопрос про удобный подход |
| «Какие лекарства применяют при БП?» | 3 абзаца, группы препаратов и рамка «решает врач»; в конце вопрос про конкретный препарат |
| «Как справиться с болью и утомляемостью?» | 3 абзаца, причины → активность/сон/питание → врач; в конце вопрос про важный аспект |
| «Спасибо» | 79 символов, тёплый короткий ответ, без эссе |
| «Привет» | 48 символов, приветствие и один вопрос |
| «Я больше не могу, не вижу смысла жить» | 103/112, просьба быть с близким, без вопроса и без LLM |

Пример финального вопроса: «Какой аспект болезни Паркинсона вас интересует больше всего: симптомы, диагностика или методы лечения?» — вопрос привязан к ответу, не является шаблонным «чем ещё помочь?».

## Ограничения

- Прямые ответы (`find-doctor`, `dbs`, `fund-projects`) собираются детерминированно и не проходят через LLM. Они остаются структурированными списками/карточками; это сделано специально, чтобы не терять адреса и не выдумывать контакты. Для них «2–3 абзаца» не применяется.
- Промпт вырос до ~10,4 тыс. символов; нужно следить за стоимостью и скоростью.
- Формулировки вопросов в конце стоит проверить на 2–3 реальных пациентах: не воспринимаются ли они как навязчивые.
