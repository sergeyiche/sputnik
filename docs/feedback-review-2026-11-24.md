## 2. Что подтвердилось

### 2.1. СБН: вопрос ушёл в подбор врача

Подтверждено. На «что говорят врачи о синдроме беспокойных ног» ассистент ответил:

> «Конечно, помогу подобрать специалиста. Подскажите, в каком городе вы находитесь?»

Причина: в `find-doctor.match_any` есть слово `врач`, а отдельного навыка по СБН нет. Формулировка «что говорят врачи» — информационный вопрос, а не поиск контакта.

**Решение:** добавить навык `rls` и исключения для `find-doctor`:
`что говорят врачи`, `мнение врачей`, `врачи советуют`, `врачи рекомендуют`, `по словам врачей`, `не нужен врач`, `не нужен специалист`.

### 2.2. Краснодар: 3 врача вместо 4

Подтверждено. В сессии источник — `Список врачей.txt`. В текущей KB:

- `Список врачей.txt` — 265 строк, 3 врача в Краснодаре;
- `Список врачей паркинсонологов.txt` — 271 строка, 4 врача в Краснодаре;
- `Список врачей с сайта.txt` — 270 строк, 4 врача в Краснодаре.

`find-doctor` до сих пор смотрит в старый `Список врачей.txt`, поэтому теряет Хатхе Ю.А.

**Решение:** выбрать один канонический список, обновить `clarify.source` и `retrieval_boost`, старые списки убрать из индекса или помечать как архивные.

### 2.3. Адыгея: специалист есть, но регион не сопоставлен

Подтверждено. В `Список врачей паркинсонологов.txt` есть:

- Хатхе Юлия Анатольевна, Майкоп, Клиника «Гиппократ».

Но `extract_city` ищет город, а не регион: «Адыгея» не равно «Майкоп». Поэтому ассистент отвечает «нет врачей из города Адыгея».

**Решение:** добавить `region_aliases`:
`Адыгея` / `Республика Адыгея` → `Майкоп`; `Краснодарский край` → `Краснодар`.
Плюс canonical city: «Майкоп», а в ответе можно писать «Майкоп (Республика Адыгея)».

### 2.4. Анализы при СБН: контекст потерян

Подтверждено. Ход:

1. «может быть сдать какие то анализы» → ассистент дал общий анализ мочи и УЗИ мочевого пузыря;
2. после «нет, анализы при синдроме беспокойных ног» → дал ферритин, железо, ЭНМГ.

Причина: сообщение 197 не содержит «СБН» и не распознано как продолжение темы; поиск ушёл в урологию. Отдельно: в `СБН.txt` на слайде 14 перечислены мочевина, креатинин, глюкоза, магний, ТТГ, B12, фолат, но **нет ферритина/сывороточного железа**. Ферритин есть в `вся инфа из эфиров для Агента БП 2.0.txt`, `Основная информация...`, `Диспансеризация при БП.txt`.

**Решение:**
- считать «может быть…» / «а какие анализы…» продолжением темы;
- добавить `rls` навык с boost `СБН.txt` + профильные фрагменты про ферритин;
- в `query_hints` добавить «ферритин сывороточное железо»;
- проверить/дополнить `СБН.txt` строкой про ферритин.

### 2.5. Частое мочеиспускание: самопомощь и уход к врачу

Подтверждено частично. В первом ответе сессии 2 были общие советы (жидкость, кофеин, Кегель, питание), но источник был `правовая поддержка БП 2026.txt` — не по теме. После «нет возможности к специалисту» ассистент ответил «подберу специалиста», а затем «нет врачей из города **них**».

Сейчас новый материал `Проблемы_с_мочеиспусканием_при_БП.txt` и `Рена Малик...` дают хороший ответ на прямой запрос. Но фраза «мне не нужен врач» всё ещё включает `find-doctor`.

**Решение:** добавить навык `urinary` с boost на `Проблемы_с_мочеиспусканием_при_БП.txt` и `Рена Малик...`, тезисом «сначала практическая самопомощь, к врачу — если не помогает/есть красные флаги». Добавить `find-doctor.avoid_any` для «не нужен врач».

### 2.6. Баг «город них»

Подтверждён. В `dialogue_memories` сессии 2 сохранено `city = "них"`. Причина — regex `_CITY` в `packages/dialogue/memory.py`: `я из` совпало внутри «информация из них».

**Решение:** word boundary + стоп-слова (`них`, `него`, `нее`, `меня`, `вас`, `нас`), не сохранять город короче 3 букв и без совпадения с каталогом/регионом.

### 2.7. DBS: неполный и затем неверный список

Подтверждено. На «где в России делают операции по DBS» ассистент выдал 3 адреса Москвы. На «а в других городах?» — список Санкт-Петербурга/Екатеринбурга/Новосибирска/Казани, причём часть адресов не соответствует KB (например, НИИ Бурденко в Санкт-Петербурге). На «это все адреса?» — ответил, что точных адресов нет.

В `какие операции при БП.txt` есть 10 центров DBS:

- Москва — 3;
- Санкт-Петербург — 2;
- Тюмень — 1;
- Новосибирск — 2;
- Владивосток — 1;
- Казань — 1.

**Решение:** навык `dbs` + детерминированное извлечение нумерованного списка из `какие операции при БП.txt`. Не отдавать это на top-k/LLM.

### 2.8. Проекты фонда: неполный перечень

Подтверждено. На «расскажи про все проекты» ассистент выдал 1, затем 3 проекта. В новом `ИИ навигатор по проектам фонда.txt` есть 8 разделов:

1.1 Игры Паркинсона  
1.2 Команда Мечты  
1.3 Онлайн-марафон «Готов Побеждать Паркинсона»  
1.4 Генетические исследования  
1.5 Творческий онлайн-клуб «ДО-ФА-МИ»  
1.6 Танцы онлайн  
1.7 Клуб создателей системы  
1.8 Стратегия развития 2026–2027

Причина: `fund-projects.lookup.source` и `retrieval_boost` всё ещё указывают на старый `Навигатор по проектам фонда.txt`, которого в KB уже нет. Плюс нет режима «все проекты».

**Решение:** обновить источник на `ИИ навигатор по проектам фонда.txt`, добавить all-режим: при «все проекты / какие проекты / полный список» отдавать все разделы 1.1–1.7 (1.8 — стратегия, не проект) с коротким описанием.

### 2.9. Правовая сессия

Подтверждено: сессия 4 отработала хорошо, пользователь сам отметил. Вмешательство не требуется, кроме наблюдения за устаревшими названиями ведомств.

## 3. Что пользователь сформулировал неточно

- «3 случайных проекта» — это не случайная выборка, а top-k retrieval + устаревший lookup. Проекты выбираются по релевантности, но неполно.
- «3 специалиста, хотя в базе больше» — верно по факту, но причина не в лимите `max_rows`, а в том, что выбран старый файл из трёх.
- «Агент настойчиво отправляет к специалистам» — в первом ответе сессии 2 были общие советы, но источник был не по теме; настойчивость появилась на следующем ходе из-за `find-doctor`.
- «После замечания даёт правильный ответ» — верно, но текущий самостоятельный ответ по анализам СБН не содержит ферритина: это content-gap, а не стабильное решение.
- «Адыгея» — специалист есть в Майкопе; нужен региональный alias, а не новый врач.

## 4. План изменений

### P0 — точность и маршрутизация

1. **Один канонический список врачей.** Выбрать `Список врачей паркинсонологов.txt` (271 строка, 4 Краснодар, Майкоп) или `Список врачей с сайта.txt` (270 строк, 4 Краснодар, Майкоп). Старый `Список врачей.txt` (265, без Майкопа) убрать из boost/индекса или пометить архивным.
2. **`find-doctor`:** обновить `clarify.source` и `retrieval_boost`; добавить `region_aliases`; расширить `avoid_any` фразами про «что говорят врачи» и «не нужен врач».
3. **Новый навык `rls`:** `match_any` — `сбн`, `синдром беспокойных ног`, `беспокойные ноги`; boost — `СБН.txt` + профильные фрагменты про ферритин; body — не уходить в урологию, проверять ферритин/железо, при лекарствах — к врачу.
4. **Новый навык `urinary`:** boost — `Проблемы_с_мочеиспусканием_при_БП.txt`, `Рена Малик...`; body — сначала практическая самопомощь, затем красные флаги/врач.
5. **Новый навык `dbs`:** детерминированный список 10 центров из `какие операции при БП.txt`; при вопросе «все адреса» — все 10, без LLM.
6. **`fund-projects`:** источник — `ИИ навигатор по проектам фонда.txt`; all-режим для 1.1–1.7; обновить конкретные headings.
7. **Память:** исправить `_CITY` (word boundary + стоп-слова), чтобы «информация из них» не становилась городом.
8. **Контекст:** считать «может быть…» продолжением темы; для СБН/урологии не терять тему при коротких уточнениях.
